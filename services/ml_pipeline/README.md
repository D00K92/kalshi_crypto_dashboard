# ML Pipeline

`ml_pipeline` owns model training, evaluation, retraining decisions, and Vertex
AI lifecycle operations. Feature and target generation, Feast definitions, and
online-store materialization are owned by `batch_etl`.

### Current input layout:

```text
gs://<bucket>/processed/resampled_market_data/frequency=<1s|5s|1m|5m|10m|30m|1h>/date=<yyyy-mm-dd>/hour=<hh>/*.parquet
```

Current feature output layout:

```text
gs://<bucket>/features/frequency=<1s|5s|1m|5m|10m|30m|1h>/date=<yyyy-mm-dd>/hour=<hh>/*.parquet
```

The active v1 Feast source is `gs://kalshi-crypto-tick-data/features/v1`, with
`asset` and `frequency` as entities and Redis as the online store. Apply the
repository from the Feast-isolated environment, then materialize after each
hourly feature write:

```bash
cd ../batch_etl/feature_store
feast apply
python ../src/kalshi_crypto_batch_etl/jobs/materialize_feast.py --repo .
```

Historical training must use `src/components/fetch_historical_features.py` with
an entity dataframe containing `event_timestamp`; join future-volatility targets
only after Feast returns the point-in-time feature rows.


### Scope:

- Kubeflow pipeline definitions
- KFP components written in Python
- model training, validation, and evaluation jobs
- Vertex AI model registration and deployment
- point-in-time historical feature retrieval through the Feast contract owned by
  `batch_etl`

### how everything fits together for 50-100 features

[ Hourly CronJob (GKE) ]
  └─► Runs `src/jobs/hourly_feature_gen.py`
  └─► Computes 100 features in Polars (`src/features/compute_v2.py`)
  └─► Writes Parquet to `gs://.../features/v2/year=2026/month=09/day=03/hour=11.parquet`

[ Hourly Sync Job (GKE) ]
  └─► Runs `uv run feast materialize`
  └─► Loads last 1h features from Parquet into Redis (Sub-1ms ready)

[ Kubeflow Training Pipeline (GKE) ]
  └─► Component `fetch_historical.py` calls `feast_store.get_historical_features()`
  └─► Gets Point-in-Time accurate 100-feature dataset (No data leakage)
  └─► Trains XGBoost / PyTorch model -> Registers output in Vertex AI Registry
